# temper-deploy

The GitOps state of [Temper](https://github.com/dohr-michael/temper). **What is on a branch
here is what is running** — ArgoCD reconciles it, and nothing else writes to the cluster.

CI in the product repository never talks to Kubernetes. It builds the two images, pushes them
to `ghcr.io`, and commits a **digest** here. That commit is the deploy.

This repository is a *source*, not an owner: the ArgoCD `Application` that points at it lives
in the infra repository, together with the namespace it targets. Everything below is written
from that side of the boundary.

## The branches

| Branch | Namespace | Host | How it moves | The Application in infra |
|---|---|---|---|---|
| `dev` | `temper-dev` | `temper-dev.dohrm.fr` | CI pushes straight to it on every push to `temper@main` | `automated`, `prune`, `selfHeal` |
| `prod` | `temper-prod` | — | CI opens a pull request on a `v*` tag; **a human merges it** | no `automated` — the merge is the decision, the sync is the act |

The two branches differ in exactly three things, and adding a fourth is a design change:

1. the image digests in `kustomization.yaml`,
2. the ConfigMap literals in `kustomization.yaml`,
3. the ingress host in `ingress.yaml`.

There are no overlays. With a branch per environment, an overlay would be a second axis saying
the same thing, and "what is deployed on dev" would have two answers.

## What infra must provide

The Application, per environment:

```yaml
source:
  repoURL: https://github.com/dohr-michael/temper-deploy.git
  targetRevision: dev        # or `prod`
  path: .
destination:
  namespace: temper-dev      # or `temper-prod`
```

`spec.destination.namespace` is the **only** place the namespace is named — nothing here
carries one, so the two can never disagree. `CreateNamespace=true` should stay off: if the
namespace is missing, the sync must fail rather than manufacture an empty one without the
Secret in it.

And in that namespace, before the first sync:

- `Secret/infra-secrets`, key `MONGO_URI_SECRET` — a MongoDB connection URI **on a replica
  set** (the API writes an event and its snapshot in one transaction, and MongoDB only offers
  transactions on a replica set). It is the only value in this deployment that carries a
  credential; nothing here creates it, reads it back, or prunes it, and a missing Secret is a
  pod that never starts;
- if `ghcr.io/dohr-michael/temper-*` is private, an image pull secret and a `default`
  ServiceAccount referencing it.

Everything else the deployment needs is public and lives in the ConfigMap generated by
`kustomization.yaml`: an authorization-code + PKCE flow has no client secret, and the
authority, client id and audience are all visible in the browser's first redirect.

## TLS

Not here. **Caddy sits in front of the cluster** and owns both the certificate and the Let's
Encrypt account; Traefik only ever sees plain http from it, which is why `ingress.yaml` binds
the `web` entrypoint and carries no `tls:` section. What this repository needs from that side
is only that the host in the table above resolves to Caddy and that Caddy forwards it to the
ingress — and that Auth0's Allowed Callback URLs name the same host, in `https`.

## What CI pushes

`temper@.github/workflows/deploy.yaml` runs `kustomize edit set image` at the root of a
checkout of this repository, then commits. That is why `kustomization.yaml` is at the root and
why the digests are the only thing it rewrites.

## Shape

```
kustomization.yaml     # what ArgoCD renders (path `.`): resources, image digests, ConfigMap
api.deployment.yaml    # the Rust API — ClusterIP only, no ingress
api.service.yaml
web.deployment.yaml    # the portal on spa-server: static assets + /config.js + proxy to the API
web.service.yaml
ingress.yaml           # the single entry point; the API is reached through the portal's origin
```

## Locally

```bash
kustomize build .
```

That is also the gate: `.github/workflows/validate.yaml` runs it on every push and pull
request, and on `prod` additionally refuses an image that is not pinned to a digest.

## Rolling back

Revert the commit that moved the digest. On `dev` ArgoCD picks it up by itself; on `prod` it is
a pull request like any other.
